# Backend configuration reference

`.env.example` is the complete backend template. `python -m backend.ops.init_env`
creates a new private `.env`, generates four independent secrets and refuses
existing files/symlinks. POSIX creation mode is 0600; Windows operators must use
appropriate filesystem ACLs. No secret is printed. The helper creates no database
or account and changes no existing credential.

For native execution, `Settings.from_env()` loads the root `.env` without
overriding exported variables. Compose also gives exported variables precedence
over its `.env` interpolation. Restart processes after changing configuration.
Secrets are excluded from settings repr and API/operational metadata.

## Database and HTTP

| Variable | Default/template | Meaning |
| --- | --- | --- |
| `MEDILINK_DB_NAME` | `medilink` | Existing native DB or new Compose DB name |
| `MEDILINK_DB_HOST` | `localhost` | Native host/socket directory; Compose fixes it to `db` |
| `MEDILINK_DB_PORT` | `5432` | Native port 1–65535; Compose fixes internal port to 5432 |
| `MEDILINK_DB_USER` | `postgres` in template | Native role / Compose bootstrap role |
| `MEDILINK_DB_PASSWORD` | blank; generated by helper | Match native role; initializes NEW Compose volume only |
| `MEDILINK_DB_CONNECT_TIMEOUT` | `5` | Positive connection timeout in seconds |
| `MEDILINK_DB_STATEMENT_TIMEOUT_MS` | `5000` | Positive SQL statement timeout in milliseconds |
| `MEDILINK_CORS_ORIGINS` | localhost/127.0.0.1 port 5173 | Comma-separated allowed browser origins |
| `MEDILINK_API_PORT` | `8000` | Compose loopback host port; native Uvicorn uses its CLI `--port` |

Compose forwards configurable scalar backend settings; host/port/storage are
fixed to its internal database and private volume paths. PostgreSQL is not
published to the host. Its bootstrap role also runs migrations in this development
stack. A production deployment needs its own role/secret/backup policies.

## Authentication and risk

| Variable | Default | Meaning |
| --- | --- | --- |
| `MEDILINK_JWT_SECRET` | blank | Patient/staff access and short-lived staff-stage signing |
| `MEDILINK_CARD_SECRET` | blank | Separate HMAC signing key for staff QR cards |
| `MEDILINK_ACTION_SIGNING_SECRET` | blank | Separate MCP approved-action signing key |
| `MEDILINK_ACCESS_TOKEN_MINUTES` | `60` | Access-token lifetime, 1–480 minutes |
| `MEDILINK_MEDIUM_RISK_REVIEW` | `required` | `required` or audited `automatic`; high risk always needs a human |
| `MEDILINK_APPROVAL_TTL_MINUTES` | `60` | Review lifetime, 1–1440 minutes |

Use independent random secrets of at least 32 characters. Missing/placeholder
keys fail closed where used. Share the action key only with trusted MCP context
verifiers; do not give it to the browser or agent. Rotation invalidates outstanding
corresponding tokens/cards; refresh affected approvals/configuration deliberately.
Staff stage tokens expire after five minutes and cannot be exchanged twice.
There is no refresh-token or public staff-bypass endpoint. Current DB role/active
status is checked on authenticated requests. Access JWTs are signed, not encrypted.

## Documents

| Variable | Default | Meaning |
| --- | --- | --- |
| `MEDILINK_DOCUMENT_STORAGE_DIR` | `./var/documents` | Native private root; relative to repository, or absolute |
| `MEDILINK_DOCUMENT_MAX_BYTES` | `5242880` | Upload limit; allowed 1–25 MiB |
| `MEDILINK_DOCUMENT_MAX_IMAGE_PIXELS` | `20000000` | Positive decompressed image pixel limit |
| `MEDILINK_DOCUMENT_MAX_PDF_PAGES` | `100` | Positive page limit |

Compose fixes storage to `/app/var/documents` in a persistent named volume.
Do not serve that directory through a public web server. Clients use authenticated
content routes. Raw sources, extraction results and workflow references have
separate storage/permission boundaries. OCR/vision/speech production is owned by
the AI member; the backend provides persistent worker claim/result contracts.

## Hospital MCP, graph and recovery

| Variable | Default | Meaning |
| --- | --- | --- |
| `MEDILINK_MCP_CONFIG_FILE` | blank | Operator JSON file; path must be readable in the executing environment |
| `MEDILINK_GRAPH_SERVICE_URL` | blank | Graph-owner HTTP facade, not a native NebulaGraph port |
| `MEDILINK_GRAPH_SERVICE_TOKEN` | blank | Server-side graph credential; required for remote hosts |
| `MEDILINK_GRAPH_TIMEOUT_SECONDS` | `10` | 0.1–60 seconds |
| `MEDILINK_GRAPH_MAX_RESULTS` | `100` | 1–200 bounded reference items |
| `MEDILINK_RECOVERY_SERVICE_URL` | blank | Read-only durable action-receipt facade |
| `MEDILINK_RECOVERY_SERVICE_TOKEN` | blank | Server-side receipt-service credential; required remotely |
| `MEDILINK_RECOVERY_TIMEOUT_SECONDS` | `10` | 0.1–60 seconds |
| `MEDILINK_RECONCILIATION_STALE_SECONDS` | `300` | Pending-write age before lookup, 300–86400 seconds |

Blank endpoints leave integrations unconfigured. Native loopback HTTP is allowed
for development; remote HTTP endpoints require HTTPS according to the existing
transport policies. Do not point a native HTTP URL at a service's database port.
Remote graph/recovery require service tokens. Hospital HTTP tokens are named by
`bearer_token_env`; stdio `env_vars` explicitly allowlist inherited variables.
There is no global credential inheritance or automatic retry of uncertain writes.

In containers, `localhost` means the container. Use actual reachable HTTPS service
URLs or a reviewed transport arrangement consistent with the policies. Mount an
operator-owned MCP configuration read-only and explicitly pass its named token
variables using a local Compose override. For example, the relevant additions are:

```yaml
services:
  backend:
    environment:
      MEDILINK_MCP_CONFIG_FILE: /run/medilink/mcp.json
      MEDILINK_EHR_MCP_TOKEN: ${MEDILINK_EHR_MCP_TOKEN:?Set EHR service token}
    volumes:
      - ./backend/config/mcp.local.json:/run/medilink/mcp.json:ro
```

The corresponding JSON can select `streamable_http`, an actual operator-provided
HTTPS EHR URL, `bearer_token_env: MEDILINK_EHR_MCP_TOKEN` and a bounded timeout.
Do not copy the Part 4 legacy stdio example into the backend-only image unchanged:
that image deliberately excludes the project's MCP implementation. The receiving
MCP owner must verify approved-action context and deduplicate writes durably.

## Development and optional integrations

`MEDILINK_TEST_DB_DSN` is an explicit opt-in to an empty disposable database.
`MEDILINK_BENCHMARK_ADMIN_DSN` permits the benchmark to create/drop only a unique
benchmark database. Neither belongs in the application `.env` template. See the
verification commands in [Part 9](part-9.md).

`OPENAI_API_KEY` and `OPENAI_MODEL` remain optional legacy/AI-owner settings; the
existing template model string is retained for compatibility. They are unused by
the backend-only factory and not passed to its Compose image. Face enrollment and
optional biometric libraries are also separate from the foundation dependencies.
No real patient data, credentials or biometric references belong in source control.
